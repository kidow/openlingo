# 언어별 날짜 학습 기록 설계

Date: 2026-04-25
Status: Draft

## 요약

`docs/studies/<lang>/<date>.md` 아래에 실제로 공부한 내용을 날짜별로 기록한다. 기존 `src/content/notes/`는 언어별 참고 메모로 유지하고, `docs/researches/`는 조사 자료로 유지한다. 새 `docs/studies/`는 학습자가 그날 학습한 내용, 예문, 헷갈린 점, 복습 항목을 남기는 복습용 지식 베이스로 사용한다.

## 배경

OpenLingo에는 이미 앱에서 렌더링하는 언어별 노트인 `src/content/notes/*.mdx`와, 언어별 조사 자료를 담는 `docs/researches/`가 있다. 하지만 매일 실제로 공부한 내용을 시간순으로 남기는 공간은 분리되어 있지 않다.

이번 설계는 참고용 메모, 리서치 문서, 실제 학습 기록을 구분한다. 학습 기록은 완성된 설명 문서가 아니라 복습 가능한 학습 로그다. 따라서 언어별 흐름을 따라가기 쉽고, 날짜별로 쌓이는 구조가 필요하다.

## 목표

- 언어별 학습 기록을 `docs/studies/<lang>/<date>.md` 구조로 저장한다.
- 각 파일은 하루 동안 해당 언어를 공부한 내용을 담는다.
- frontmatter로 언어, 날짜, 주제, 수준, 출처, 복습일을 기록한다.
- 본문은 고정 섹션을 제공하되, 학습 내용에 따라 자유롭게 확장할 수 있다.
- 기존 `src/content/notes/`와 `docs/researches/`의 역할을 침범하지 않는다.

## 비목표

- 학습 기록을 앱 화면에 노출하지 않는다.
- 자동 진도 관리, 점수화, 통계 시스템을 만들지 않는다.
- 기존 notes 문서를 날짜별 로그로 재구성하지 않는다.
- 기존 researches 문서를 studies 아래로 옮기지 않는다.
- 새 테스트를 만들지 않는다.

## 권장 구조

학습 기록은 언어 코드별 폴더 아래 날짜 파일로 둔다.

```text
docs/
  studies/
    ja/
      2026-04-25.md
    en/
      2026-04-25.md
    ar/
      2026-04-25.md
```

이 구조는 “특정 언어를 어떻게 공부해왔는가”를 따라가기 좋다. 복습도 보통 언어 단위로 이루어지므로, 날짜 폴더보다 언어 폴더가 더 자연스럽다.

## 폴더명 판단

`docs/studies`는 이 용도에 적절하다.

- `src/content/notes/`: 앱에서 읽는 언어별 참고 메모
- `docs/researches/`: 외부 자료 조사, 시험 정보, 언어 배경 정리
- `docs/studies/`: 실제 학습한 내용의 날짜별 기록

`study-logs`는 의미가 더 직접적이지만, 기존 `researches`와 나란히 둘 때 이름이 길고 튄다. `studies`는 짧고, 문서 폴더 아래의 학습 기록이라는 의미도 충분히 전달된다.

## 파일명 규칙

날짜 파일명은 ISO 날짜를 사용한다.

```text
YYYY-MM-DD.md
```

예시는 다음과 같다.

```text
docs/studies/ja/2026-04-25.md
docs/studies/en/2026-04-25.md
docs/studies/zh-hans/2026-04-25.md
```

언어 코드는 프로젝트에서 이미 쓰는 코드와 맞춘다. 예를 들어 간체 중국어는 `zh-hans`, 번체 중국어는 `zh-hant`를 사용한다.

## Frontmatter 규약

각 학습 기록 파일은 다음 frontmatter를 가진다.

```md
---
title: "일본어 학습 기록"
lang: "ja"
date: "2026-04-25"
topics: ["문법", "어휘"]
level: "beginner"
source: []
reviewAfter: "2026-04-26"
---
```

필드는 다음 의미를 가진다.

- `title`: 문서 제목
- `lang`: 언어 코드
- `date`: 학습일
- `topics`: 그날 다룬 주제 목록
- `level`: 학습 난이도 또는 체감 수준
- `source`: 교재, 영상, 문서, 링크 등 출처 목록
- `reviewAfter`: 다음 복습 권장일

`topics`, `source`, `reviewAfter`는 필요에 따라 비워둘 수 있다. 다만 필드 자체는 유지해서 파일 간 형태를 맞춘다.

## 본문 템플릿

본문은 다음 섹션을 기본으로 둔다.

```md
## 배운 것

## 예문

## 헷갈린 점

## 복습할 것
```

필요하면 다음 섹션을 추가할 수 있다.

- `## 발음`
- `## 단어`
- `## 문법`
- `## 다음에 확인할 것`

기본 섹션의 목적은 매일 작성 부담을 줄이는 것이다. 모든 섹션을 채워야 하는 것은 아니며, 실제로 공부한 내용만 기록한다.

## 작성 규칙

- 문서는 한국어로 작성한다.
- 새 학습 기록을 추가하기 전, 같은 언어와 같은 날짜의 파일이 이미 있는지 확인한다.
- 이미 파일이 있으면 새 파일을 만들지 않고 기존 파일을 갱신한다.
- 날짜가 다르면 같은 언어 폴더 아래 새 파일을 만든다.
- 출처가 있는 학습 내용은 `source` 또는 본문에 남긴다.
- 복습에 필요한 예문과 헷갈린 점을 우선 기록한다.

## 기존 문서와의 관계

`src/content/notes/`는 계속 참고 메모 역할을 한다. 여러 날 반복해서 중요해진 내용이나 정리된 설명은 별도 요청이 있을 때 notes 문서에 반영할 수 있다.

`docs/researches/`는 조사 자료 역할을 한다. 시험 정보, 커리큘럼, 외부 자료 비교처럼 학습 전후에 참고하는 문서는 researches에 둔다.

`docs/studies/`는 실제 학습 행위를 기록한다. 같은 내용이 researches나 notes와 일부 겹쳐도 괜찮지만, 기록의 기준은 “그날 실제로 공부했는가”다.

## 오류 처리와 유지보수

같은 날짜에 같은 언어 파일이 중복되면 하나로 합친다. 언어 코드가 기존 프로젝트 코드와 다르면 새 코드를 만들기 전에 기존 코드 체계를 확인한다.

frontmatter 날짜와 파일명이 다르면 파일명을 기준으로 맞춘다. 예를 들어 `docs/studies/ja/2026-04-25.md`의 `date`가 `2026-04-24`라면 `date`를 `2026-04-25`로 수정한다.

## 검증 기준

이 설계가 만족되려면 다음 조건을 충족해야 한다.

- `docs/studies/<lang>/<date>.md` 구조를 사용한다.
- 언어별 폴더명은 프로젝트 언어 코드와 맞는다.
- 각 파일에는 frontmatter가 있다.
- 각 파일에는 기본 본문 섹션이 있다.
- 기존 notes, researches 문서의 역할과 충돌하지 않는다.
